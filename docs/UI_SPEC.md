\# 32. SEO



Implement the UI with SEO best practices in mind.



SEO is part of the frontend structure only.



Do not implement SEO through backend logic or external SEO services.



For every page:



\* Use an appropriate and unique `<title>`.

\* Add a relevant meta description.

\* Use appropriate canonical metadata where applicable.

\* Use semantic page structure.

\* Use one clear `<h1>` per page where appropriate.

\* Use `<h2>` and `<h3>` for section hierarchy.

\* Use descriptive text for important content.

\* Use meaningful URLs and route structure.

\* Use descriptive link text.

\* Use descriptive `alt` text for meaningful images.

\* Use empty alt text (`alt=""`) for decorative images.

\* Do not put important text inside images.

\* Keep heading hierarchy logical.

\* Avoid unnecessary heading tags.

\* Make product names, categories and important content crawlable in the HTML.

\* Avoid using JavaScript-only rendering for important static content when a semantic HTML element can be used.

\* Use proper `<a>` links for navigation instead of clickable `<div>` elements.

\* Use proper buttons for actions.

\* Use semantic forms and labels.



For product pages, prepare the UI structure so that Product structured data can be added later.



For category and product listing pages:



\* Use semantic headings.

\* Use crawlable product links.

\* Use meaningful product names.

\* Keep important product information in the HTML.



Do not add fake SEO content or keyword stuffing.



Do not generate fake reviews, fake ratings, fake company information, or fake claims only for SEO.

\# 33. SEMANTIC HTML



Use semantic HTML throughout the application.



Prefer semantic elements over generic `<div>` elements whenever appropriate.



Use:



\* `<header>` for page and section headers

\* `<nav>` for navigation

\* `<main>` for the primary page content

\* `<section>` for meaningful sections

\* `<article>` for independent content such as products or blog-like content

\* `<aside>` for secondary content and filters

\* `<footer>` for footer content

\* `<form>` for forms

\* `<fieldset>` and `<legend>` where appropriate for grouped form controls

\* `<label>` for form inputs

\* `<button>` for actions

\* `<a>` / Next.js `Link` for navigation

\* `<ul>` / `<ol>` for lists

\* `<table>` for actual tabular data such as order history when appropriate



Do not use:



```tsx

<div onClick={...}>

```



when the element is actually a button.



Do not use:



```tsx

<div>

&#x20; Product

</div>

```



when the content is better represented by an appropriate semantic element.



Do not use buttons for navigation when a link is appropriate.



Do not use links for actions when a button is appropriate.



Keep the HTML structure accessible and meaningful even without CSS.

\* Accessible dialogs and drawers

\* Correct landmark elements

\* Sufficient color contrast

\* `aria-label` only when the visible text does not provide an accessible name

\* `aria-expanded` for expandable controls when required

\* `aria-current` where appropriate

\* `aria-hidden` only when appropriate



Do not add unnecessary ARIA attributes.



Prefer native HTML semantics over ARIA whenever possible.
